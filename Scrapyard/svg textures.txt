I would like to create a java utility that can create a png file and load into memory dynamically. how?
To create a PNG image programmatically and load it dynamically into memory in Java, you can use BufferedImage for in-memory drawing, ImageIO to write it out to a file, and ByteArrayInputStream or ImageIO.read() to reload it dynamically.

Java Code Example
java
import java.awt.Graphics2D;
import java.awt.Color;
import java.awt.image.BufferedImage;
import javax.imageio.ImageIO;
import java.io.File;
import java.io.ByteArrayOutputStream;
import java.io.ByteArrayInputStream;
import java.io.IOException;

public class DynamicPngUtility {

    public static void main(String[] args) {
        String filePath = "dynamic_output.png";
        
        try {
            // 1. Create a BufferedImage in memory (Width: 300, Height: 200)
            BufferedImage bufferedImage = new BufferedImage(300, 200, BufferedImage.TYPE_INT_ARGB);
            
            // 2. Draw dynamically on the image using Graphics2D
            Graphics2D g2d = bufferedImage.createGraphics();
            g2d.setColor(Color.BLUE);
            g2d.fillRect(0, 0, 300, 200); // Draw background
            g2d.setColor(Color.WHITE);
            g2d.drawString("Dynamic PNG in Java!", 50, 100); // Draw text
            g2d.dispose();
            
            // 3. Save the BufferedImage as a physical PNG file
            File outputFile = new File(filePath);
            ImageIO.write(bufferedImage, "png", outputFile);
            System.out.println("PNG file created successfully at: " + outputFile.getAbsolutePath());
            
            // 4. Dynamically load the PNG file back into memory as a fresh object
            BufferedImage reloadedImage = ImageIO.read(outputFile);
            System.out.println("PNG loaded back into memory! Dimensions: " 
                + reloadedImage.getWidth() + "x" + reloadedImage.getHeight());
                
            // Alternative: Load directly from byte array without hitting disk storage
            ByteArrayOutputStream baos = new ByteArrayOutputStream();
            ImageIO.write(bufferedImage, "png", baos);
            byte[] imageBytes = baos.toByteArray();
            
            BufferedImage memoryLoadedImage = ImageIO.read(new ByteArrayInputStream(imageBytes));
            System.out.println("PNG loaded dynamically straight from byte array memory!");

        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

I'm thinking about procedurally generating small textures to use in forge 1.20.1, understanding that I would need to find a way around having it load from disk and straight from a memory location.
To dynamically inject procedurally generated textures into Minecraft Forge 1.20.1 straight from memory, you cannot use standard file-based resource packs. Instead, you need to use Forge/Minecraft's native texture management system: TextureManager and DynamicTexture.
DynamicTexture wraps a standard Minecraft NativeImage (which holds raw pixel data in memory) and uploads it directly to the GPU as a ResourceLocation identifier that any block, item, or GUI can reference.
Here is the exact approach to generate textures dynamically and register them directly in memory.
The Dynamic Texture Utility Class
java
import net.minecraft.client.Minecraft;
import net.minecraft.client.renderer.texture.DynamicTexture;
import net.minecraft.client.renderer.texture.TextureManager;
import com.mojang.blaze3d.platform.NativeImage;
import net.minecraft.resources.ResourceLocation;

public class ProceduralTextureUtility {

    /**
     * Generates a dynamic texture in memory and registers it with Minecraft's TextureManager.
     * 
     * @param modId Your Mod's ID (used for the namespace)
     * @param textureName A unique identifier for this texture instance (e.g., "procedural_stone_1")
     * @param width Width of the texture (e.g., 16 for standard Minecraft blocks)
     * @param height Height of the texture
     * @return A ResourceLocation you can pass directly to renderers or models
     */
    public static ResourceLocation generateAndRegisterTexture(String modId, String textureName, int width, int height) {
        // 1. Allocate native memory for the pixel buffer (RGBA format)
        NativeImage nativeImage = new NativeImage(NativeImage.Format.RGBA, width, height, false);

        // 2. Procedurally generate your pixels loop
        for (int x = 0; x < width; x++) {
            for (int y = 0; y < height; y++) {
                // Example: Create a simple procedural noise pattern
                int r = (int) (Math.random() * 255);
                int g = (int) (Math.random() * 255);
                int b = (int) (Math.random() * 255);
                int a = 255; // Fully opaque

                // Combine channels into an ABGR int format expected by NativeImage
                int abgrColor = (a << 24) | (b << 16) | (g << 8) | r;
                
                nativeImage.setPixelRGBA(x, y, abgrColor);
            }
        }

        // 3. Wrap the native image in a DynamicTexture
        DynamicTexture dynamicTexture = new DynamicTexture(nativeImage);

        // 4. Create the synthetic path identifier
        ResourceLocation location = new ResourceLocation(modId, "textures/dynamic/" + textureName + ".png");

        // 5. Register straight to Minecraft's GPU manager (Bypasses disk storage)
        TextureManager textureManager = Minecraft.getInstance().getTextureManager();
        textureManager.register(location, dynamicTexture);

        return location;
    }
}
Use code with caution.
Critical Rules for 1.20.1 Implementation
ABGR format requirement: Unlike typical Java AWT graphics which default to ARGB, Minecraft's internal NativeImage mapping utilizes ABGR bit order for native OpenGL optimization. Pay close attention to channel packing (a << 24 | b << 16 | g << 8 | r).
Client-Side Only: This generation process references Minecraft.getInstance().getTextureManager(), meaning this utility must only be executed on the physical client. Running this on a dedicated server environment will result in a hard crash (ClassNotFoundException on client rendering classes).
Binding the Texture: Once your method outputs the ResourceLocation, you can use it in custom block entity renderers (BERs), Screen/GUI graphics contexts, or custom model overrides via RenderType.entitySolid(location) or RenderType.guiTexture(location).

java
import com.github.weisj.jsvg.SVGDocument;
import com.github.weisj.jsvg.parser.SVGLoader;
import com.mojang.blaze3d.platform.NativeImage;
import net.minecraft.client.Minecraft;
import net.minecraft.client.renderer.texture.DynamicTexture;
import net.minecraft.resources.ResourceLocation;
import java.awt.*;
import java.awt.image.BufferedImage;
import java.io.InputStream;

public class SvgTextureUtility {

    /**
     * Loads an SVG file from resources, rasterizes it to a specific size, and registers it to memory.
     * 
     * @param modId Your Mod's ID
     * @param textureName Unique output texture name
     * @param svgResourcePath Path to the SVG inside your resources (e.g., "assets/mymod/svg/logo.svg")
     * @param targetSize The desired width/height resolution to render the texture at
     */
    public static ResourceLocation loadSvgAsDynamicTexture(String modId, String textureName, String svgResourcePath, int targetSize) {
        try {
            // 1. Locate and load the SVG from your mod resources
            InputStream inputStream = Minecraft.getInstance().getResourceManager()
                    .getResource(new ResourceLocation(modId, svgResourcePath))
                    .orElseThrow(() -> new IllegalArgumentException("SVG file not found"))
                    .open();

            SVGLoader loader = new SVGLoader();
            SVGDocument svgDocument = loader.load(inputStream);

            if (svgDocument == null) {
                throw new RuntimeException("Failed to parse SVG data.");
            }

            // 2. Create a standard Java BufferedImage buffer to render into
            BufferedImage bufferedImage = new BufferedImage(targetSize, targetSize, BufferedImage.TYPE_INT_ARGB);
            Graphics2D g2d = bufferedImage.createGraphics();

            // Enable anti-aliasing for smooth scaling if desired
            g2d.setRenderingHint(RenderingHints.KEY_ANTIALIASING, RenderingHints.VALUE_ANTIALIAS_ON);

            // 3. Let JSVG render the vector shapes directly onto our canvas
            // We pass the g2d context and a bounding box matching our desired output size
            svgDocument.render(null, g2d, new Rectangle(0, 0, targetSize, targetSize));
            g2d.dispose();

            // 4. Convert the AWT BufferedImage over to Minecraft's NativeImage (ABGR format)
            NativeImage nativeImage = new NativeImage(NativeImage.Format.RGBA, targetSize, targetSize, false);
            for (int x = 0; x < targetSize; x++) {
                for (int y = 0; y < targetSize; y++) {
                    int argbColor = bufferedImage.getRGB(x, y);
                    
                    // Unpack ARGB channels
                    int a = (argbColor >> 24) & 0xFF;
                    int r = (argbColor >> 16) & 0xFF;
                    int g = (argbColor >> 8) & 0xFF;
                    int b = argbColor & 0xFF;

                    // Pack into ABGR for Minecraft's NativeImage
                    int abgrColor = (a << 24) | (b << 16) | (g << 8) | r;
                    nativeImage.setPixelRGBA(x, y, abgrColor);
                }
            }

            // 5. Wrap, create ResourceLocation, and upload to the GPU
            DynamicTexture dynamicTexture = new DynamicTexture(nativeImage);
            ResourceLocation location = new ResourceLocation(modId, "textures/dynamic/" + textureName + ".png");
            
            Minecraft.getInstance().getTextureManager().register(location, dynamicTexture);

            return location;

        } catch (Exception e) {
            e.printStackTrace();
            // Fallback to missing texture indicator if rendering fails
            return new ResourceLocation("minecraft", "missingno");
        }
    }
}
Use code with caution.
The Infinite Resolution Advantage
By combining SVGs with dynamic textures, you unlock a major superpower: Dynamic Level of Detail (LOD).
Because it is a vector graphic, you can call this function passing targetSize = 16 for far-away blocks, or regenerate it passing targetSize = 256 if the player gets closer or opens a high-resolution GUI. The SVG stays perfectly crisp at any resolution without consuming extra storage space on disk.

are alpha channels handled? I can make an aura effect or something?
Yes, alpha channels are completely supported. Both the JSVG parsing library and Minecraft's internal NativeImage mapping handle the transparency (alpha) layer seamlessly.
This means you can easily create glowing auras, smoke drifts, semi-transparent energy shields, or smooth gradients that blend perfectly with the game world.
How SVG Alpha Translates to Minecraft
When you define transparency in your SVG using features like opacity, fill-opacity, or gradient stops with transparency (stop-opacity), JSVG paints those values correctly onto the BufferedImage.
Because our conversion loop explicitly extracts the alpha channel:

int a = (argbColor >> 24) & 0xFF; // Extracts the opacity value (0 to 255)

For a clean, glowing aura texture, you can design an SVG utilizing a <radialGradient> that fades out towards the edges, using low-opacity colors. Here is a raw SVG string pattern that creates a beautiful, semi-transparent magic circle/aura effect:

The Rendering Trap to Avoid in Forge
While the texture will successfully possess transparency in memory, Minecraft will discard the alpha channel and render it completely solid if you use the wrong rendering pass.
To ensure Minecraft respects the alpha channel when rendering your dynamic texture onto a block, entity, or item, you must choose a RenderType that supports transparency.
What you are rendering	Correct Render Type to Use	Behavior
Custom Block / Entity	RenderType.entityTranslucent(resourceLocation)	Blends smoothly; handles gradients and partial opacities.
Cutout Blocks (like Glass)	RenderType.cutout()	Binary transparency (either 100% visible or 100% invisible). Avoid for auras!
GUI / Screen Overlay	RenderType.guiComponent() or RenderType.guiTexture()	Standard UI blending. Make sure to call RenderSystem.enableBlend() right before drawing.
