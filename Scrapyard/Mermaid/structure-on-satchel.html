Structure on Satchel

How Structure (Cairn) rides Satchel: one persisted, server-side LevelJig holding Cairn records. A record is created when Boss reports a positioned boss on a large enough border, placed on a later tick, and punished with an explosion when its cap is broken. BlockBreakSignal is the only Forge signal it handles.

module registration (JigConfig) Satchel runtime bundle / fixture state module handler / logic outside this module
How to read it

How to read it: the module's init() hands each JigConfig to Satchel.registerJigConfig. Satchel builds the jig on each side the config applies to and opens one scope per level or player. The scope engine creates the bundle and its fixtures, calls each fixture's onJigTick every tick, and on each execution pulse flushes dirty bundles to SavedData or sends them to the client, if the config allows it. Handlers are attached to SatchelEventBus, which is shared by every jig, so each ScopeEvent handler checks the jig key before doing anything. Signals are bare Forge events that a Satchel ingress class re-posts on the same bus. "Serialized" fixtures register NBT fields, so they're what gets persisted and synced. "Live only" fixtures register none.
